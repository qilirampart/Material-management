# 覆盖升级依赖残留与目录入口修复

## 根因与现场恢复

v0.5.5 更新后出现 `module 'numpy' has no attribute 'short'`。新包不含 NumPy，但原安装位置 `_internal/numpy` 和 `numpy.libs` 仍有旧扩展文件；不存在 `__init__.py`，被识别为空命名空间。`openpyxl.compat.numbers` 的可选导入成功，访问 `numpy.short` 时崩溃。

已用 `python -I -S`、空 NumPy 命名空间与原 openpyxl 兼容模块复现相同异常；本机安装目录的残留结构吻合。仅将这两个已确认的残留目录移动至 `output/upgrade-numpy-repair/quarantine`，不删除文件。恢复清单为 `repair.json`。

修复后的本机安装版以独立配置执行 `--smoke-ui` 成功：`output/upgrade-numpy-repair/runtime-test/evidence/result.json`。没有改动业务配置或素材。

## 永久修复

Inno Setup 在安装第一步通过 [`InstallDelete`](https://jrsoftware.org/inno-setup/documentation/topic_installdeletesection.htm) 清理准确的 `{app}\_internal`，再写入新依赖。禁止清理 `{app}` 整体及用户 runtime/output。现有版本使用的配置、素材和登录数据均在该依赖目录之外。

增加 `UpgradeTestBuild` 专用安装器：不写卸载注册表、不创建用户快捷方式。`scripts/verify_windows_upgrade.py` 在自有临时目录预置 NumPy 和其他过期依赖、模拟用户配置/视频/批次记录；执行安装，核对旧依赖移除与用户文件原样保留，再运行安装后的程序。

本地安装器验证复用了已发布 v0.5.5 的程序载荷，仅验证更新后的安装行为；最终 v0.5.6 由发布流水线重新构建并执行相同验收。

首次隔离测试发现 `/NOICONS` 未阻止无条件开始菜单项，已给测试构建增加编译期禁用 `[Icons]`；受影响的测试快捷方式已恢复至原软件位置。正式安装器快捷方式行为不变。

## 素材目录入口

目录不存在时，QFileSystemModel 的无效根索引会显示计算机磁盘；打开不存在的路径又未检查返回结果。现在不绑定无效模型，显示缺失目录说明；“打开素材目录”询问创建，错误提示清楚，创建后刷新目录。测试覆盖取消、创建、根目录限定和系统打开失败。

## 验证记录

- 29 项相关测试：28 项通过，1 项因 Windows 符号链接权限跳过，`tmp/v0.5.6-affected-tests.log`。

- 缺失目录 UI：`output/missing-root-fix/missing-root.png`，不显示磁盘列表，预览禁用。
- Windows CI 同时执行原有打包检查与新增的覆盖安装/用户数据保留检查；失败时不发布安装包。
