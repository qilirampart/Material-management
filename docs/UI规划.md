# 素材投放助手 UI 规划

2026-09-05，设计评审稿。目标形态：Windows 桌面工具，下载与片头检测优先，内部网站登录和上传逐步推进。

生图视觉参考：`assets/ui/download-and-platform-v1.png`，使用内置 image_gen 生成。图中的视频ID、缩略图及部分文字是示意；功能行为以本规划和可交互原型为准。生成提示词保存在 `assets/ui/download-and-platform-v1.prompt.txt`。

可交互原型：`output/ui/material-workbench.html`。已通过浏览器实测：四页导航、上传准备面板展开/收起、状态筛选、首帧加载正常，1024/736/360px下无整体横向溢出，运行无脚本错误；已检查明暗主题。原型只展示交互，不执行下载、模型调用或上传。

## 核心布局

左侧导航：**下载与检测 / 素材复核 / 平台工作台 / 设置**。底部固定显示当前任务状态和最近一条提示。

默认打开“下载与检测”，优先呈现正在执行或最近一次批次。1366×768 是主要布局基准；窄窗口下详情从右侧面板改为单独详情页，保证表格和操作按钮可用。

## 1. 下载与检测（第一期实现重点）

顶部：导入 Excel、新建批次、历史批次。导入后展示剧名、有效视频数、重复数和异常行；遇到错误只定位异常行，不让用户猜表头和链接规则。

主操作：开始下载并检测 / 暂停 / 继续 / 重试失败 / 导出结果。高级下拉提供“只下载”，默认完整执行下载与检测。点击开始后主按钮就地变为暂停，避免同时出现相互冲突的动作。

任务列表字段：选择框、视频 ID、剧名、下载状态、片头检测状态、命中项、操作。热度、点赞数、创建时间作为可展开的次要信息，避免初始表格过宽。

摘要只显示业务进度：总数、已检测、命中拦截、待复核/失败；下载进度和检测进度分别计算，不能把“下载完成”显示成整批完成。

状态筛选：全部、待处理、处理中、命中拦截、待复核、片头抽检未发现。支持剧名/视频 ID 查询。多选操作针对当前所选条目，不自动作用于隐藏结果。

运行中：切换页面不终止任务；暂停停止领取新任务，当前网络调用/步骤安全结束后停下并保存。关闭有运行任务的窗口时给出“保存进度并退出 / 继续运行”选择。

空态：中央导入区，提示所需表头并提供输入示例。批次完成：摘要和结果导出入口。单条错误：原因和重试按钮，不反复弹窗打断整批。

## 2. 素材复核

同一套批次数据的复核视图，不另建一套结果。可从任务列表直接打开某一条素材。

左侧素材列表；中间视频播放器和首帧、1秒、2秒三张证据图；右侧是检测结果、命中文字、logo证据、实际取帧时间和人工备注。点击证据图可放大，点击时间定位原视频。

明显展示“仅片头三帧”。展示模型转录的原文，避免只有一个“通过/失败”结论。Logo 参考图放在证据旁的可展开区域，不混进视频证据编号。

第一期复核动作：查看本地视频、查看原链接、打开文件位置、重新检测、添加备注、人工确认拦截。对于模型阳性保留“不上传”的业务规则，不提供无记录的一键跳过。

人工认为误判时先记录意见并重新检测；将来如业务需要人工放行，应单独对齐权限和规则，保存原自动结果、操作者、时间与理由。

## 3. 平台工作台（分阶段开放）

**方向：内置浏览器显示公司原始网站，用户自行登录。**

工作台包含“网站”和“上传队列”两个子页。登录或查看平台时浏览器占满内容区；准备/执行上传时在侧边展开任务和字段预览。不要把网站永久压缩到一个小角落。

网站工具栏：后退、前进、刷新、回到平台首页、当前站点、登录状态、当前账号、重新登录。地址和站点由设置指定，具体网址尚待提供。弹窗、单点登录、扫码和内网访问兼容性在接入阶段实测。

登录：展示网站自身登录界面，不另做一套公司账号密码表单。账号身份以网站真实登录信息为依据，未识别时显示“待确认”，不能只因网页打开就显示已登录。按本机使用者隔离浏览器会话；明确切换账号会影响后续任务。

上传字段按来源分层：

| 层级 | 典型信息（示例，待网站对齐） | UI归属 | 生效时机 |
|---|---|---|---|
| 固定信息 | 素材来源、固定分类、业务类型 | 上传模板 | 新建上传批次时带入 |
| 上传人信息 | 当前账号、所属团队、人员归属 | 平台账号区/个人默认项 | 从真实登录状态或明确选择带入 |
| 批次信息 | 当前剧目、渠道、统一标签 | 上传准备页 | 当前批次共享，可逐条覆盖允许修改的项 |
| 单条素材信息 | 文件、视频ID、标题、时长、对应剧目 | 素材字段预览 | 从实际下载文件和需求表填入 |

每个预填项显示来源，例如“来自模板”“来自登录账号”“来自需求表”“手动修改”。实际哪些字段固定、哪些随上传人或内容变化，等看到网站后再定，原型里的字段不是接口约定。

优先级：单条手动值 > 批次值 > 模板默认值；上传账号由实际会话确定，不能被普通字段覆盖。每次创建上传任务保存一份字段快照，避免修改模板意外改变正在上传的任务。

未来上传步骤：选择候选素材 → 核对字段及缺失项 → 用户启动本批上传 → 显示逐条执行 → 保存平台回执。

只允许检测完整且无命中、文件有效、必填项完整的记录进入候选；命中、待复核、未检测不能加入。登录失效暂停队列，用户登录后续跑；账号变化先暂停并提示重新核对归属。

上传状态独立于下载/检测：未加入、待上传、上传中、成功、失败、结果待确认。提交超时不自动盲重试；先查网站是否已生成记录，避免重复上传。成功需保存平台素材ID或可验证回执，不能仅凭按钮点击成功。

## 4. 设置

- 下载：保存目录、批次命名、重试参数，浏览器异常提示。
- 检测：抽帧策略（默认0/1/2秒，首帧必选）、禁用表达、红果logo参考图、模型配置选择、连接测试。
- 平台：站点地址、登录会话、上传模板（后续启用）。
- 常规：最近批次、日志位置、结果保存位置。

API地址、密钥、模型参数放在设置内，任务页只显示“检测模型已配置/需配置”；不要求投放人员在主流程理解接口细节。

修改检测规则生成新规则版本。旧结果保留原版本，界面显示“规则已更新，需重新检测”，不可把旧结论当成新规则结果。

## 交付阶段

1. **第一期桌面 UI**：导入、批次列表、下载检测、暂停续跑、结果表、视频与证据复核、检测设置。平台工作台保留入口并显示“待接入”。
2. **登录与人工操作**：接入实际网站，验证内置浏览器登录、会话保留、账号识别、网站手动上传兼容性。
3. **辅助上传**：模板与字段映射、逐条预填/选择文件，用户可查看网站并处理网站提示。
4. **批量上传**：规则稳定后接入队列、暂停恢复、去重和结果回写。若公司提供合适的正式接口，再评估以接口执行上传、浏览器用于登录和核验。

## 技术落地建议

已实现 PySide6 桌面外壳，延续现有 Python 下载和检测服务；主页面采用原生表格、播放器和侧栏，平台区使用 WebEngine。第一期提供批次导入/恢复、状态筛选、后台运行与暂停、证据复核、人工备注及设置；尚未验证目标内网站点兼容性。

后台任务通过独立进程和本地事件文件传递进度给 UI，主线程不运行下载、FFmpeg 或模型请求。批次状态存储继续复用现有模型，人工备注单独保存。网站浏览独立封装，上传自动化尚未实现。

## 验收重点

- 200条任务批量运行时 UI 可交互，页面切换不丢进度，关闭/重启可恢复。
- 命中行可直接看到实际帧与文字/logo证据；待复核与无命中状态不能混淆。
- 登录状态与上传人身份可见；换账号不会静默改变已准备任务的归属。
- 上传成功、失败和结果待确认都有明确证据与下一步；未接入时不展示虚假的已登录/已上传状态。
- 1366×768及125%系统缩放下主操作可达；更窄时详情变为单独页，不靠缩小字体塞进窗口。
