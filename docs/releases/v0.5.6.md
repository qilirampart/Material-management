# v0.5.6 覆盖升级启动修复

## 修复升级后无法启动

修复覆盖安装后弹出 `module 'numpy' has no attribute 'short'`、软件无法启动的问题。旧安装目录中的可选依赖残留会被误识别为可用组件。

安装器现在替换 `_internal` 内置依赖目录，避免把新旧依赖混在一起；保留安装目录之外和根目录中的配置、素材、批次记录及登录数据。请勿将业务数据存放在 `_internal` 内。

**已经无法启动的电脑，请使用完整安装包覆盖安装到原位置**，不需要先卸载，也不要删除素材或配置目录。完整包无需 VPN 安装，可由同事直接分发。

Windows 完整包：**DianzhongMaterialAssistant-Setup-0.5.6.exe**。正常启动的旧版也可以使用“设置 → 软件更新”；访问 GitHub 和下载更新前请开启 VPN。

## 修复打开素材目录没有反应

- 保存目录不存在时，询问是否创建并打开；也可取消并在设置中选择实际素材目录。
- 创建或系统打开失败时显示具体提示。
- 目录不存在时显示明确的空状态，不再退回整台电脑的磁盘列表，也不能预览删除范围。

## 验证

已在本机复现残留 NumPy 导致的启动异常，并通过隔离残留恢复安装版运行。新增真实覆盖安装验收：预置旧依赖，执行测试安装器，确认旧依赖移除、模拟配置和素材保留，再启动安装后的程序验证浏览器、加工、播放和清理。此验收已加入 Windows 发布必过检查。

macOS 同步提供构建包；本次安装器修复针对 Windows，macOS 尚无真实设备验收。
