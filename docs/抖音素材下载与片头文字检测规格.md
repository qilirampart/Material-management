# 抖音素材下载与片头文字检测（第一期）

状态：2026-09-05 用户补充模型来源与明确检测项后进入实现；真实验证情况见使用说明。

## 目标与范围

从需求方 Excel 批量下载抖音视频，抽取片头三帧，通过图片识别模型检测“免费观看”等引导文字，保存原视频、证据帧与结果表。第一期不调用内部上传平台。

默认在当前工作区建设独立 Python 批处理工具，先跑通流程；业务操作界面另行对齐。参考项目只作为源码参考，配置、输出和日志独立保存。

## 已核实输入

- 文件：`懂小剧素材_婚房门后的秘密.xlsx`，工作表：`懂小剧素材`。
- 列：剧名、视频ID、热度、点赞数、创建时间、原始链接。
- 200 条记录，均为《婚房门后的秘密》，200 个唯一视频 ID。
- 无缺失链接，所有视频 ID 与原始链接末段一致。
- 视频 ID 按字符串读取，保留原行号和全部业务字段；不覆盖原表。
- 后续输入支持表头校验、空行跳过、重复 ID 去重下载并回填各原始行。无效行单独报告。

## 抽帧与识别规则

1. 默认抽取播放时间 0、1、2 秒，共三张，首张取解码得到的首帧，不能用平台封面代替。
2. 短视频不足以覆盖计划时间点时，在有效时长内调整取点并记录实际时间；不足三张独立帧时标记待复核，不复制图片凑数。
3. 三张原比例图片交给视觉模型，要求逐帧输出可见文字、命中短语、证据对应帧及不确定情况。不把标题、网页按钮或音频内容作为画面文字证据。
4. 用户明确检测项：“0元免费看”“免费看”“一分钱不花”、红果 logo；保留原始要求“免费观看”，同时支持“0元免费看”的变体“0元观看”。单独出现“免费”不直接判为违规。logo 使用 `assets/references/hongguo_logo.png` 中上方图标作视觉参考；下方说明和单选按钮不是 logo，参考图片本身不得计作素材命中。
5. 文字存在空格、换行、繁简体变体时做归一化匹配，同时保留原始识别文本；模型补充语义判断，不能凭空补齐模糊文字。
6. 任意一帧有明确命中即拦截；三帧全部有效且无命中才标记“片头抽检未发现”。模型超时、响应格式错误、模糊或缺帧均进入待复核。
7. 保存模型名称、规则版本、实际取帧时间及识别结果，使结果可追溯。模型与密钥通过本地配置或环境变量注入，密钥不写入报告与版本库。

片头抽检不能证明全片无相关文字，也可能漏过两次采样之间的短暂提示。本期结果名称不得使用“全片合格”。后续若要求全片保证，需要另行扩大采样范围和人工复核策略。

## 状态与后续上传衔接

| 状态 | 含义 | 后续上传处理 |
|---|---|---|
| 待处理 | 尚未下载或识别 | 排除 |
| 下载失败 | 无有效本地视频 | 排除，可重试 |
| 待复核 | 抽帧/模型失败或判断不确定 | 排除 |
| 命中拦截 | 至少一帧命中禁用表达 | 排除，保留视频和证据 |
| 片头抽检未发现 | 三帧成功识别且无命中 | 仅作为未来上传候选 |

第一期所有记录均为未上传。上传候选与上传完成分别记录，未来平台还需定义剧目映射、去重标识和接口认证。

## 输出、恢复与错误处理

- `output/<批次>/videos/<视频ID>.mp4`：下载完成并验证后的原视频。
- `output/<批次>/frames/<视频ID>/`：三帧及时间信息。
- `output/<批次>/results.json`：逐条结构化结果；每条任务结束原子保存。
- `output/<批次>/检测结果.xlsx`：原始六列，加下载状态、本地路径、抽检状态、命中文字、证据帧路径、失败原因、检测范围及模型名称。
- 同批次重启读取已有进度，验证本地文件后跳过成功下载；规则或模型变化时重新检测，不盲目复用旧结论。
- 下载采用临时文件，校验后改为正式文件名；中断残片不能当成下载完成。单条失败不终止整个批次。
- 起步串行下载，网络请求设置超时和有限重试；浏览器需要登录或验证时记录明确原因。

## 技术与目录约定

Python + requests + openpyxl + FFmpeg/ffprobe；浏览器兜底使用原项目 PySide6 WebEngine。图片模型只读加载 `E:\点众\YouTube字幕核验助手工作区\runtime\api_config.json` 中启用的语言模型配置，目前为 `qwen3-vl-flash`，采用该项目封面检测模块相同的多模态 Chat Completions 接口。密钥仅在内存中使用。

`src/` 放 Excel 导入、下载、抽帧、检测、批次编排及结果导出模块；`tests/` 放行为测试；`config.example.json` 仅存无密钥配置模板；`docs/` 放规格和使用说明。

保持函数职责单一，路径用 `Path`，网络失败与检测结论分离。例如：

## 实施顺序与验收

1. 导入及下载：实现表头映射、ID 校验和下载链路。验收 200 条输入无丢失；小批真实下载成功，可解码且检查音轨；失败有记录。
2. 抽帧及识别：验证首帧确实为第一解码帧；用带目标文字、无目标文字和短视频夹具测试；真实模型样本保留响应和证据。
3. 批次和报告：覆盖命中、未命中、模型超时、非法响应、缺帧、重复 ID、中断恢复。确认所有失败和未处理状态均不进入上传候选；重新打开结果表核对记录和证据路径。
4. 先完成三条真实样本检查，再运行全量。若缺少可用模型配置，完成本地下载与抽帧验证并明确记录模型联调未完成，不能报告已通过检测。
