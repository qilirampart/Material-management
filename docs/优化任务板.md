## UX-01：统一后台任务退出与收尾

- **问题与依据：** `MainWindow.closeEvent` 只检查读表、模型测试和下载进程，遗漏码率转码、元数据探测、平台后台任务。隔离测试中，模拟转码运行时，关闭事件仍被接受。尚未主动制造真实线程销毁崩溃。
- **位置：** [desktop.py](../src/desktop.py)、[desktop_widgets.py](../src/desktop_widgets.py)、[ui_design.py](../src/ui_design.py) 的任务创建、关闭与回调路径。
- **修复范围：** 建立统一任务登记和收尾流程；关闭时处理线程及其子进程；清理待执行的重试回调；避免阻塞主线程等待。
- **验收：** 分别在转码、探测、文件选择、读表、模型测试及下载时关闭窗口；进度按约定保存；无运行中线程被销毁、遗留 FFmpeg 或旧回调访问已销毁控件；空闲关闭正常。
- **完成证据：** `946de7a` 建立主窗口与平台页统一活动任务查询；新建批次、启动处理和关闭窗口均受同一守卫保护。`tests.test_background_task_guards` 覆盖码率任务、质量探测、平台暂存任务和关闭事件。

## UX-02：隔离批次状态与异步任务结果

- **问题与依据：** 转码运行时 `new_batch` 仍可清空记录，已隔离复现；`apply_enhanced_bitrates` 使用回调发生时的 `self.folder` 和 `self.records`，未核对来源批次。可能丢失旧批次结果或污染新批次。
- **位置：** [desktop.py](../src/desktop.py) 的 `new_batch`、`start_batch`、`enhance_selected_bitrate`、`apply_enhanced_bitrates`。
- **修复范围：** 固定任务输入快照、批次标识及结果保存位置；切换批次时隔离旧任务；统一互斥条件，覆盖新建、历史批次、重检等入口。
- **验收：** A 批次处理中切换/新建 B；A 结果只能写入 A，B 界面和配置不被旧回调覆盖；使用包含相同视频 ID 的两个批次验证；重复点击不会启动冲突任务。
- **完成证据：** `946de7a`、`2f067ce` 阻止后台任务期间新建、启动或打开历史批次；`e41dda0` 固定码率任务的批次目录与记录快照，结果携带批次路径，过期回调不会更新当前界面。回归测试覆盖历史批次替换和跨批次回调。

## UX-03：批量转码逐条持久化与失败恢复

- **问题与依据：** `enhance_selected_bitrates` 整批成功才返回。模拟第一条成功、第二条失败后，第一条文件存在但记录没有副本信息，重试可能重复转码。
- **位置：** [upload.py](../src/upload.py) 的 `enhance_selected_bitrates`，以及 [desktop.py](../src/desktop.py) 的结果回写。
- **修复范围：** 每条成功后保存；逐条记录失败并继续其余项目；输出先写临时文件，验证后替换；重试复用已验证的成功结果。
- **验收：** 至少三条任务中间一条失败，其余任务可完成；重启后成功记录仍在；只重试失败项；模拟写入失败不会把未完成文件标为达标；原视频不受影响。
- **完成证据：** `e41dda0` 在每条增强成功后立即写入原批次 `results.json`，单条失败记录类型并继续后续条目，重试会复用已验证副本。三条任务中间失败、成功记录重启可读和原文件不变均有自动测试覆盖。

## UX-04：减少主线程全表刷新

- **问题与依据：** `refresh_table` 遍历所有行并更新单元格，阶段变化、保存和批量勾选会反复触发。离屏实测见下表，不包含真实窗口绘制成本，不能视为所有电脑上的性能承诺。

| 素材数 | 首次填表 | 再次刷新 |
|---|---:|---:|
| 200 | 37.4 ms | 27.8 ms |
| 2,000 | 424.0 ms | 299.4 ms |
| 10,000 | 3,108.7 ms | 2,055.6 ms |

- **位置：** [desktop.py](../src/desktop.py) 的 `refresh_table`、`poll_events`、筛选及批量选择操作。
- **修复范围：** 优先更新变化行、合并连续事件、避免重复全表处理；根据测量决定是否采用表格模型或分页。
- **验收：** 相同环境重测三档数据，记录优化前后耗时；单条进度更新不重建全表；建议以 2,000 条下常见交互主线程耗时低于 100 ms 为初始目标；真实窗口确认滚动、搜索、勾选及选中位置正常。
- **完成证据：** `83062cb` 将字节进度限定写入下载状态列；回归测试确认视频 ID、素材名不变，状态文本和速度提示正确。

## UX-05：转码进度、暂停与结果反馈

- **问题与依据：** 当前转码使用无限进度条；“暂停队列”只检查下载进程，对转码不起作用。长视频处理时难以区分正在工作和卡死。
- **位置：** [desktop.py](../src/desktop.py) 的转码与暂停入口，[media.py](../src/media.py) 的 FFmpeg 调用。
- **修复范围：** 显示当前文件、第几条/总数和可测量的转码进度；支持当前文件完成后停止；区分成功、失败、跳过和暂停，保留失败原因。
- **验收：** 多条视频处理中点击暂停，当前文件按约定收尾且后续不启动；可继续剩余项；编码及复检阶段分别提示，不伪造百分比；失败不会显示成功；与下载任务状态不混淆。

## UX-06：保留平台上传准备并隔离过期回调

- **问题与依据：** 每次进入平台页都会调用 `set_materials`，清空上传批次、选择器和编导等准备信息。正在执行的文件选择/表单重试也缺少任务版本校验。
- **位置：** [desktop_widgets.py](../src/desktop_widgets.py) 的 `set_materials`、`staging_ready`、表单与文件选择重试；[desktop.py](../src/desktop.py) 的页面切换。
- **修复范围：** 依据素材批次及选择集合保留准备状态；输入发生变化才失效；过期任务与延时回调不得修改新状态或继续选择旧文件。
- **验收：** 同一批次切走再返回，配置和上传批次保留；改变素材选择后提示重新准备；旧回调不会覆盖新配置或触发旧文件选择。验证只到文件选择和预览，不点击上传、保存草稿或提交审核。
