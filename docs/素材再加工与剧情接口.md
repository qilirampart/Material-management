# 素材再加工与剧情接口

## 在独立工作区生成新版本

从侧栏进入“素材再创作”。该入口独立管理剧目、来源、成品及上传准备，不读写原“素材任务”的候选区、勾选状态和历史批次。与原平台工作台共用浏览器登录会话，页面和上传配置分开。

1. 输入剧目 ID（也可写成 `ID-剧名`），创建再创作批次；打开智投完成登录后，点击“查询本批次素材”。查询覆盖批次中所有剧目；默认上传日期为 2014-01-01 至今天，避免平台默认近 14 天的范围漏掉旧素材。
2. 查询完成后下载全部待处理素材或选中项；单次超过 20 条会先确认。下载、速度、校验和逐项完成状态分别显示；重试跳过已成功项。已有本地视频也可使用“导入已有素材”。选中来源后，点击“加工选中素材”，选择“微创新”或“仅改 MD5”，填写上传人缩写。
3. 先生成一条样片并播放检查，再批量生成，每条可生成 1–10 个版本。
4. 成品自动保存到本批次；在加工预览页选择成品和上传剧目，点击“准备本剧上传”。
5. 上传准备固定为“客户端二组”可见，沿用已有填写表单与选择文件能力；不会自动保存草稿或提交审核。不同剧目分开准备。

处理和校验在后台线程中串行执行。停止或关闭窗口会请求中止当前 FFmpeg，保留已完成成品和记录；失败项不会阻止后续素材。处理期间不接受导入成品或启动第二个加工任务。

### 当前支持

- 微创新：固定输出 720×1280；模糊或黑边背景；前景等比完整显示，不裁剪字幕；配置去头尾、0.8–1.2 倍变速、轻度调色、可选顶部文字。
- 默认组合：背景变化、去头尾与变速、画面调色，分别对应背景、时长、风格三类。自定义关闭操作后不自动宣称符合需求方的“三类”验收。
- 多版本：同一来源的不同版本使用不同调色强度；没有启用调色时，微创新只允许生成单个版本。
- 改 MD5：重新封装并设置独立元数据，音视频不重新编码；校验新旧 MD5 不同。不会改变原片的码率与尺寸，不保证平台将内容认定为新素材。
- 微创新复用现有上传转码约束：视频码率超过 3500 且不超过 5000 kbps，文件不超过 522240 KB（510 MiB）。按处理后时长计算预算，无法满足时明确失败。
- 原文件不覆盖，成品按剧名分文件夹。记录来源 ID、路径、新旧 MD5、选项、版本、输出媒体信息和失败原因。
- 成品不标记为检测通过，不继承原片的检测结论。上传沿用现有未检测本地素材的使用约定，界面明确提示尚未检测。复杂内容判断目前由用户人工完成。

批次位置：素材保存根目录下的 `素材再创作/批次编号/`，其中 `recreation.json` 保存剧目、来源及成品列表。加工输出为 `加工成品/运行编号/剧名/微创新或改md5/`；每轮有 `manifest.json`。样片也保存在成品列表，关闭加工窗口不会丢失已完成记录。独立记住最近再创作批次，可从“历史批次”打开其他批次；不改变原任务的最近批次设置。

命名：`APP-繁花-王俨-微创新或改md5-剧名-上传人缩写-日期-序号.mp4`。生成后的平台暂存命名保留对应处理类型，不改变已有非加工素材的命名规则。

## 精彩剧情选择接口

当前不自动选择精彩剧情，也不发起模型网络请求。人工可调整去头尾，复杂剧情剪辑仍需人工工具完成。

`src.material_variants.ClipSelectionProvider` 预留 Python 适配接口：

```python
def select_clips(video_path: str, metadata: dict, instruction: str) -> list[dict]:
    # start/end 单位为秒，坐标基于原视频，左闭右开。
    return [{"start": 12.0, "end": 38.5, "reason": "冲突建立"}]
```

调用方必须先使用 `validate_clip_ranges(ranges, duration)` 校验结果：非空、有限数字、严格正时长、按时间排序、不重叠、不能越过原视频边界。校验通过后仍应预览并由用户确认，才能执行剪辑。返回时间段不代表内容合规或精彩程度已被验证。

后续选择模型服务时，适配器负责接口地址、凭据管理、上传授权、超时及错误映射；模型不能返回任意 FFmpeg 命令或覆盖路径。当前仅预留协议和校验函数，未接入具体供应商、API 配置页或自动剧情重组。

## 智投采集与下载

目标流程：按多个剧目 ID，在素材管理的建议内容处查询，收集名称包含“二创”或“精剪原片”的所有素材，遍历全部分页并下载，按剧名归档，然后进入上述加工及上传准备。

2026-11-12 用户在项目窗口完成扫码。已验证实际素材管理页、建议内容按 ID 查剧、名称过滤、分页和查看源文件入口，并接通“查询本批次素材”“下载全部待处理素材”“下载选中素材”“停止”。

采集契约：`collect_all_pages` 接受网页适配器提供的 `items` 和明确的布尔 `has_next`；两类名称取并集、按素材 ID 去重、遇到重复页或无法确认分页即停止报错，每页即时落盘。每个关键词的总数在翻页中发生变化时停止并提示重新查询，避免宣称已采全。改变批次的剧目或日期范围需要新建批次，原记录和文件保留。

平台读取在本流程自己的浏览器页面内执行，复用页面现有 `$ax` 请求机制，不读取或导出 Cookie、密码或令牌。已观察的只读操作为 `/data/1097`（建议内容查询）、`/material/material/cardList`（素材分页）、`/material/material/material_source_url`（原始素材地址）。从源码和实际响应确认参数及字段后才接入，未猜测接口路径。

查询请求至少间隔 3 秒。实测快速翻页曾返回 HTTP 429，现按限流等待时间退避重试，等待过程可停止。达到重试上限会报告失败并保留已收集结果，不切换网络绕过限流。

原始地址解析在已登录页面中完成。已验证素材域名为 `https://material.wuread.cn`，文件可直接通过 HTTPS 流式下载，无须导出登录凭据；不跟随未知域名重定向，资源地址不写入批次记录或错误日志。每条先保存 `.part` 文件，检查传输长度并完整解码校验后才转成最终视频，按剧名存放在 `原始素材/来源素材ID.mp4`。已下载文件自动复用，中断或失败项可重新下载；不会覆盖原始成功文件。磁盘空间不足时明确报错。

任务在后台运行，窗口保持可操作。停止中断查询等待或视频传输；关闭主窗口时会先请求停止，再保存进度退出。当前采集或下载任务内禁止切换批次。单次查询和下载不自动触发加工或上传，用户先看到数量再决定下载范围。

随机镜像、抽帧、场景重排和背景音乐替换未默认加入，以免破坏对白、字幕或剧情顺序。

## 验证记录

### 2026-11-12 稳定性加固

- 原始视频遇到连接中断、超时、传输不完整或 HTTP 408/429/500/502/503/504 时，最多尝试 3 次；两次重试分别等待 2 秒、4 秒。等待期间可停止，界面显示重试次数。403 等非临时 HTTP 错误不重复请求；磁盘错误直接报告。
- 重试从头写入本次 `.part` 文件，不做字节续传，不覆盖已完成原视频。失败信息不包含签名资源地址。
- 恢复下载时，若最终视频已经落盘，先完整校验并补回批次记录，不再先请求可能过期的平台地址。重新打开批次时，将中断的查询恢复为暂停，下载恢复为待处理；运行中的只读界面刷新不改写状态。
