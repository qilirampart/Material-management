## 设置与状态

模型支持新增、编辑、选择和删除配置，字段含配置名称、API 地址、模型名、API Key（默认遮挡）。测试必须发送图片验证视觉能力，在后台运行并设置超时；保存和测试应分别反馈结果。配置只存本机，不写入任务日志或发布包。

检测规则可编辑禁用短语、查看或替换红果参考图。首期红果检测属于必要规则；设计图中的开关落地时应改成“已启用”的状态显示，避免随意关闭后仍被判为完整检测。规则或模型变化使旧结果标记需要重检。短片抽帧自动适配，仍保证实际首帧。

补充素材目录、并发上限（初始 2，限制 1–3）、恢复上次批次、打开日志及脱敏诊断导出。恢复批次仅恢复列表和进度，不未经用户操作自动启动未完成任务。不以清理配置、删除素材作为常规维护步骤。

复核保留自动结果与人工记录，不覆盖原始证据；命中与不确定项都不进入未来上传队列。概念图中的素材列表名称、计数为示例，实际筛选计数必须一致；包括无命中项时应命名“复核素材”，而非全部称为待复核。

## GitHub 更新流程

参考已读取的字幕核验助手 app/services/update_service.py：读取版本清单、按平台选择安装包、下载到 .part、SHA-256 验证后替换为有效包。未创建 GitHub 仓库或发布版本；本项目仓库与发布地址待实际发布时配置。不得沿用参考项目的应用 ID、发布地址或用户数据路径。

1. 启动后异步检查（可关闭）或点击“检查更新”，读取本项目 GitHub Releases 的版本信息、发布说明、包大小和校验信息。
2. 有更新时显示当前版本、新版本和说明，由用户点击下载。检查失败仅提示重试，不阻断下载/检测，也不把检查失败显示为已是最新版。
3. 后台下载，支持明确的下载进度与失败重试，完成后核验完整性；校验失败不得启动安装。
4. 下载完成显示“重启并更新”。任务运行时提供“任务结束后更新”，停止调度新任务，等待当前工作结束，持久化进度后关闭软件。不得强制中断视频写入。
5. 外部安装/更新进程等待主进程退出，只替换程序文件，再启动新版。用户无需手动卸载或删除旧目录。首次安装与升级沿用本项目固定安装标识。
6. 更新失败保留现有可用程序和用户数据；配置迁移前备份，迁移失败保留原文件并给出恢复入口。数据库/配置版本升级需可重复执行，避免重复覆盖用户值。

## 保留数据的目录约束

目标方案：程序目录与用户数据目录分离。安装后的配置、历史索引、日志、浏览器 profile 放在固定的本机用户数据目录（例如 %LOCALAPPDATA%/DianzhongMaterialAssistant），视频和证据仍保存在用户指定目录。升级包不包含用户密钥、用户配置、浏览器会话和下载素材。

当前 src/paths.py 默认 DATA_ROOT 为应用目录，需要在更新功能实现前做一次兼容迁移：识别旧 runtime/output 路径；先备份并迁移配置与索引，保留视频原路径，验证能重新打开历史批次；成功后写迁移标记。不得仅更改 DATA_ROOT 后导致用户看似丢失配置。浏览器 profile 迁移必须在浏览器关闭后进行，升级不清空 profile。保留会话数据不保证网站永不要求重新登录。

默认配置只补充缺失字段，不能覆盖现有值。安装脚本不得递归删除用户数据目录；更新包校验值从受控发布渠道读取，发布流程与来源保持一致。

## 实现时验收

- 从已配置旧版升级：模型配置和密钥、检测规则、素材目录、历史任务、人工备注与浏览器数据均保留；旧素材仍可播放、查看证据。
- 检查失败、网络断开、包损坏、磁盘不足、安装失败：旧程序和用户数据仍可用。
- 两项后台任务运行时检查及下载更新，界面可响应，点击更新不截断在写视频。
- 新版启动验证配置迁移；关闭再打开仍使用迁移后的设置，不重复迁移或还原默认值。
- 安装包和 GitHub 提交不含真实密钥、内部平台登录数据或素材。
